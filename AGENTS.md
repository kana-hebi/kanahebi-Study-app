# Project work rules

- Read `README.md`, `STATUS.md` and relevant specifications before work. Reconcile current claims with source/build/test artifacts.
- Update the single `STATUS.md` at run start and end. Keep execution gates in `docs/AUTONOMOUS_RUN.md`; do not create another current-status document.
- GitHub is the canonical project storage. Confirm remote persistence of milestones. Never force-push.
- Preserve offline core learning, smartphone use and subject-independent declarative packs.
- Free Study recording defaults ON. OFF sessions are ephemeral and must never mutate personalization/history/review.
- Treat explicit unknown separately from wrong choices and preserve first-recall evidence after help.
- Add app-native packs through developer authoring/validation. Never execute pack-supplied code.
- Verify stateful changes with meaningful tests. Clearly distinguish automated checks, compiled builds and real-device checks.
- Keep secrets, signing credentials and private learner data out of the public repository.
- User delegates routine implementation decisions. Do not halt for intermediate design approvals.
